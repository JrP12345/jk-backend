# Ekavyu authorized local VAPT — 2026-10-04

## Scope and method

Authorized assessment of local source, synthetic fixtures, and existing audit
evidence. No production/staging, third-party provider, real patient data, email,
SMS, payment, refund, migration, or destructive action was used.

Reviewed tenant/object guards, session and MFA paths, sensitive mutations,
appointment/clinical/payment transitions, webhooks, uploads, CORS/CSRF,
WebSocket/SSE authority, browser storage and DOM sinks, external fetches, logs,
configuration, request limits, and pagination. The assessment reuses prior Phase
1 audits. It applies [OWASP authorization guidance](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html),
[OWASP redirect guidance](https://cheatsheetseries.owasp.org/cheatsheets/Unvalidated_Redirects_and_Forwards_Cheat_Sheet.html),
[OWASP WebSocket guidance](https://cheatsheetseries.owasp.org/cheatsheets/WebSocket_Security_Cheat_Sheet.html),
and [Fastify validation documentation](https://fastify.dev/docs/latest/Reference/Validation-and-Serialization/).

## High vulnerabilities

### VAPT-01 — fixed: organization notification HTML injection and unvalidated navigation

| Field | Evidence |
| --- | --- |
| Severity | High / P1 before remediation |
| Affected route/components | `POST /api/notifications/send`; dashboard notification page and dropdown navigate to stored `actionUrl` |
| Attack prerequisite | Authenticated organization member with `MANAGE_ORGANIZATION`, or a compromised account with that grant |
| Safe reproduction | Submit synthetic title/message containing HTML markup and an `actionUrl` of `https://attacker.invalid/login`. Before the fix, the server inserted title/message directly into generated email HTML and persisted the URL. The dashboard passed it to `router.push`. No email was sent. |
| Expected behavior | Manual notifications render text as text and link only to an approved Ekavyu route. |
| Actual behavior before fix | HTML was interpolated into outbound email and arbitrary external navigation was retained. |
| Impact | A compromised or over-permissioned organization admin could send organization-branded phishing emails and notifications to staff. This did not grant cross-tenant data access by itself. |
| Root cause | No boundary validation for manual action URLs and raw values in an HTML template. |
| Smallest safe fix | Encode title, message and category; reject manual action URLs except relative `/dashboard` and `/track` paths; bound content size. |
| Regression case | `tests/manualNotificationContent.test.ts` encodes HTML and rejects absolute, protocol-relative and `javascript:` targets while retaining valid dashboard/tracker URLs. |

Implemented in `utilities/manualNotificationContent.ts` and
`routes/notifications.ts`. The guard runs before persistence, in-app delivery and
email outbox creation.

## False positives

- Patient, encounter, imaging, clinical, appointment, billing and upload paths
  pair authenticated organization scope with location/patient/record checks;
  frontend identifiers are not authority.
- Imaging `dicomWebUrl` is not a backend fetch target. Preview requests use the
  operator-configured PACS base URL, reject redirects and bound response bytes;
  the frontend permits only HTTPS PACS links (or local HTTP in development).
- Payment webhooks require HMAC, server-created order/invoice/appointment
  correlation, amount comparison and conditional capture before settlement.
- Cookie-authenticated production mutations require configured Origin or
  Referer. Signed provider webhooks are exempt from CSRF and separately verified.
- Private WebSocket/SSE connections resolve persisted session authority, validate
  origin, and close on revocation or permission loss.
- A tracked-source pattern scan found no confirmed hard-coded production secret.
  Secret values were never read or reported.

## Fixes implemented

- Closed VAPT-01 with server-side HTML encoding, trusted internal-route action
  validation and bounded manual notification content.
- Added a focused synthetic regression test.
